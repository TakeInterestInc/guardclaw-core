# Bounded threat model

Assets: public-safe source/demo, explicit imported snapshot in browser memory, integrity of the review labels, user's authorization boundary. Trust boundaries: local disk file → strict JSON parser → validated DTO → text-only DOM; browser → task-owned loopback static server. The local computer/browser/extensions remain trusted.

| Threat | Controls | Residual limitation |
| --- | --- | --- |
| Imported scripts/HTML or prompt injection | createElement/textContent only; no interpreter, model, Markdown HTML, eval, or dynamic component code; CSP | Human readers can still be misled by text. Author recommendations are data, never instructions to the runtime. |
| Private logs or secret disclosure | Strict field allowlists, bounded text/arrays/bytes, common credential/control-character rejection; no raw-log ingestion; no external links/requests/persistence | Detection is partial. Arbitrary secrets and PII can resemble ordinary text. Import only intentionally prepared public-safe snapshots; no universal redaction claim. |
| Link-based exfiltration or navigation | HTTPS-only producer references, no credentials/query/fragment/encoded paths/ports/IPs; every URL rendered inert | A public-looking hostname/path could still be private or sensitive. No URL is fetched, identity checked, or promoted to trusted evidence. |
| False completion or stale claims | Status separate from stage; checklist progress only; dated passing evidence required for verified stage; observed/captured/evaluation times and freshness shown | Source identity and evidence content are producer assertions. Consistency checks do not prove real completion or independent review. |
| Fake operational approval | No approve/execute/send/deploy control; resolved outcomes displayed as producer records | Someone could misread a record as current consent; copy explicitly names the read-only boundary. |
| Local network exposure / unrelated file serving | Explicit 127.0.0.1 bind; exact route allowlist; Host check against loopback names; GET/HEAD only; no filesystem path routing | No authentication/TLS; trusted local processes can access public-safe demo routes. Do not tunnel, reverse proxy or expose this prototype. |
| Excessive payload / resource use | 256 KiB input, 100 tasks/decisions, 200 checks, 600-character summaries, fixed object structure | Browser and Node resource limits remain outside this app. |
| Dependency/runtime compromise | No runtime package installation; separately licensed Core source and Apache browser validator/registry with complete notices, no install hooks, no network setup; Node built-ins; local OFL fonts with complete notices | Node/browser and test tools are external dependencies requiring normal upkeep. |

No account integration or GuardClaw enforcement is implemented. Opt-in local snapshot transport and its trusted same-user/POSIX boundary are detailed in LOCAL_AGENT_SETUP.md; foreign browser origins, arbitrary file reads and network writes are denied. A fresh launch capability from an explicitly selected owner-only access file gates every feed read/cache response; same-user/privileged processes remain trusted and source claims are unauthenticated. This is a review surface, not a security gateway. Authorization for real work must stay in the authorized supporting system. Public hosting, license, repository, branding and security promises require explicit release review.

Optional report risks: forged reports/association, replayed old revisions, contradictory coverage/time fields, parser ambiguity, reflected source content, and confusing no-match with approval. The browser rejects duplicate keys, noninteger numeric tokens, unsupported fields/engine/IDs, invalid UTF-8, depth over six and output over 64 KiB; checks fixed semantic invariants and visibly assesses session/revision/age without authentication. Output uses only text nodes and known bounded fields. Scanner controls grant no action authority; no runner endpoint or Core file serving exists. The external manual process is not proved network-contained.
